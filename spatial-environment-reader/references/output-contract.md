# 输出契约

只在建立证据记录或编写最终报告时读取本文件。

## 结构化证据记录

`evidence.jsonl` 每行一条 JSON。建议字段：

```json
{
  "evidence_id": "E-001",
  "source_file": "方案.pdf",
  "locator": "PDF 第 12 页，右下角局部平面",
  "evidence_type": "dimension_annotation",
  "observation": "目标框前场标有净宽 2400 mm",
  "supports": ["X-03 前场净宽"],
  "confidence": "high",
  "method": "visual_read",
  "value": 2400,
  "unit": "mm",
  "depends_on": [],
  "notes": "尺寸线两端分别指向目标框边界与通道边线"
}
```

允许的 `evidence_type`：

- `explicit_text`：正文、标签、图例或说明明确写出；
- `visible_geometry`：图中直接可见的物体或空间关系；
- `dimension_annotation`：尺寸线、标高、坐标或测量标签；
- `cross_view_match`：通过共同锚点完成的跨视角配准；
- `calibrated_estimate`：满足校准条件的换算估算；
- `inference`：由一个或多个证据推导的判断；
- `unknown`：重要但现有材料无法确认的事实。

`confidence` 使用 `high`、`medium`、`low`。`inference` 和 `calibrated_estimate` 应在 `depends_on` 中列出基础证据编号；数值证据应包含单位。`source_file` 必须与来源清单中的路径一致。

## 展项空间卡

每个目标展项建议使用以下字段：

```markdown
## X-03 展项名称或暂定名

- 定位：楼层/展区/相邻锚点；证据 E-001、E-004
- 目标边界：明确 / 疑似 / 未知；标记方式
- 朝向与进入：……
- 左侧 / 右侧 / 背后 / 前场：……
- 周边类型：场景、展柜、墙体、开放区、其他展项或未知
- 明暗与视听条件：……
- 明确尺寸：……
- 互动余量：充足 / 临界 / 不足 / 无法判断；适用条件
- 主要风险：……
- 置信度：高 / 中 / 低
- 待补资料：……
```

## 最终报告结构

1. **结论摘要**：只写对决策有用且有证据的结论。
2. **材料清单与覆盖**：总文件、总页/张、已读取、失败和排除项。
3. **空间总览**：楼层/区域、目标分布、流线与主要锚点；可用简图表达。
4. **逐展项空间卡**：按编号或空间顺序排列。
5. **尺寸台账**：原值、标准化值、类型、端点、来源、证据编号、置信度。
6. **互动空间评估**：使用状态、占用关系、结论等级和条件。
7. **冲突、未知与风险**：不得埋在正文中。
8. **最小补充清单**：按对结论影响排序，写清需要的图、视角、尺寸或现场动作。
9. **证据索引**：证据编号到文件与定位符的映射。

## 表述规范

- 直接事实：“图纸标注……”“画面可见……”
- 校准估算：“以 E-012 的 1200 mm 为同平面标定，估算约……，误差主要来自……”
- 推断：“由 E-003 与 E-007 推断……，置信度中。”
- 未知：“当前材料无法确认……；需要……”

不要写“显然”“肯定”“大约够用”这类没有判据的结论。不要为完成表格而补齐不存在的数据。
