# 空间环境识别

把分散在长方案和多视角截图中的文字、图像、尺寸与空间关系合并为一份可核验的展项空间判断。结论必须能回到具体文件、页码或幻灯片、图中区域和证据类型。

## 先选择工作模式

- **方案普查**：长 PDF、PPT/PPTX 或成组图片。先全量建索引，再定位展项与空间证据；不要只看搜索命中的几页。
- **单展项深化**：围绕一个框选、虚线或高亮区域，结合 CAD、SketchUp 和多角度图片建立局部空间模型。
- **缺口复核**：已有分析需要验证尺寸、位置、周边条件或互动余量。只补充能被新证据支持的结论，并保留历史不确定项。

开始前先盘点全部输入。批量材料可运行 `scripts/create_case.py` 建立文件清单和工作底稿。需要校验证据记录时运行 `scripts/validate_case.py`。工具用法与支持范围见 [references/case-tools.md](references/case-tools.md)。

## 核心约束

1. **观察、换算、推断、未知必须分开。** 图中直接可见或文字明确说明的是观察；由标尺或已知尺寸换算的是换算；跨图关系、功能和亮暗判断是推断；证据不足时写未知。
2. **不把截图像素当真实长度。** 优先采用尺寸标注、坐标、标高、图例和明确文字。只有同一平面、同一视图内存在可靠已知长度且透视影响可忽略时，才允许校准估算，并报告方法、基准、误差来源和范围。
3. **不把所有虚线或框选都认定为多媒体区。** 结合图例、引线、编号、相邻说明和跨页一致性确认语义；无法确认时写“疑似目标区域”。
4. **保留上下文。** 每个目标区域既要有局部裁切，也要保留能看出入口、流线、邻接和方向的整页或广角证据。
5. **不从效果图估算照度、净高或材质性能。** 可描述相对明暗、遮光迹象、灯具和反射风险，但不能把渲染观感当 lux、真实材质或现场条件。
6. **不越过专业边界。** 互动余量是前期可行性判断；消防疏散、无障碍、结构、机电与施工尺寸仍需当地规范、原始 CAD/BIM 或现场复核。

## 工作流

### 1. 建立来源清单与覆盖率

记录文件名、类型、页数或幻灯片数、图像尺寸、是否成功渲染、是否成功提取文字。PDF、PPT/PPTX 应同时保留：

- 可检索文字或 OCR 结果；
- 每页/每张幻灯片的完整渲染图；
- 原始页码或幻灯片编号；
- 失败、空白、密码保护、低清晰度或未支持的页面。

旧式 `.ppt` 若当前环境无法可靠渲染，要求补充导出的 PDF、PPTX 或逐页图片；不要静默跳过。格式处理细则见 [references/format-routing.md](references/format-routing.md)。

### 2. 对长方案做两遍阅读

**第一遍：全量索引。** 逐页标记页面类型、标题、展项编号、楼层/区域、是否含平面/立面/剖面/效果图/CAD/SU、疑似目标框线和尺寸。可用文字搜索辅助定位，但不能代替逐页视觉检查。

**第二遍：证据深化。** 对候选目标页及其前后关联页检查：

- 目标区边界、朝向、中心位置和进入方向；
- 周围 360° 邻接：墙、柱、门、台阶、玻璃、展柜、布景、其他展项、设备、入口和出口；
- 观众流线、停留点、排队区、观看方向和视线遮挡；
- 灯具、窗、黑箱/遮光、亮屏、反射面和相对明暗；
- 地面、顶面、壁面、设备接口、检修口和可能的安装限制；
- 所有与目标有关的数字尺寸、单位、标高、比例和图例。

### 3. 读取目标标记与文字

识别框选、虚线、色块、编号、引线和箭头，并将“标记形状”与“标记含义”分开记录。OCR 文字要回看原图，尤其复核小数点、单位、负号、中文序号和相邻尺寸串。引用说明文字时保留原意，并记录页码/幻灯片和图中位置。

### 4. 融合 CAD、SketchUp 与多角度图片

先为每张图确定视图类型：总平/平面、立面、剖面、轴测、透视、相机截图或未知。再用稳定锚点匹配视角，例如柱网、门洞、转角、展柜、楼梯、洞口、编号和特殊材质。

建立局部坐标叙述：面向目标区时的前/后/左/右/上/下，以及与入口或主流线的关系。跨视角只合并被共同锚点支持的对象；镜像、裁切、遮挡或模型版本不同要作为冲突记录。具体判读规则见 [references/spatial-reasoning.md](references/spatial-reasoning.md)。

### 5. 建立尺寸与互动空间模型

尺寸表至少区分：标注原值、单位、尺寸类型、端点/对象、所在视图、是否净尺寸、证据编号和置信度。尺寸类型包括总长、分段长、净宽、净高、标高、半径、设备尺寸、框选范围和校准估算。

互动空间不得只看框选面积。用下式组织判断，但只填入有来源的量：

`可用互动空间 = 目标区及前场净空间 − 固定障碍 − 受保护流线/疏散空间 − 设备与检修范围 − 必要安全缓冲`

同时说明：建议的观众站位与朝向、单人/多人使用方式、候场与回流、屏幕或投影观看距离、动作幅度、轮椅转身需求、运营人员位置，以及这些要求是否与既有流线重叠。若缺少真实尺寸，给出“充足 / 临界 / 不足 / 无法判断”的定性结论和所需补充材料，不编造平方米数。

### 6. 形成证据链并交叉核验

每个关键结论至少关联一个证据编号；跨视角推断通常需要两个以上独立证据。发现同一空间名称、尺寸、方向或版本不一致时，不替用户挑选一个看似合理的值，建立冲突项并指出最小复核动作。

最终检查：来源覆盖是否完整、页码是否真实、尺寸单位是否一致、裁切是否保留上下文、结论是否超出证据、未知项是否明确。证据字段和成品结构见 [references/output-contract.md](references/output-contract.md)。

## 输出要求

默认交付一份 Markdown 空间分析报告和结构化证据记录；用户指定 Word、表格或演示文稿时再转换格式。报告应让未看原文件的人能够回答：

- 展项在哪里、朝向哪里，依据是什么；
- 目标区四周分别是什么，哪些是场景、展柜、通道或其他展项；
- 有哪些明确尺寸，哪些只是估算，是否存在冲突；
- 空间相对明暗、视线和声光干扰风险如何；
- 扣除流线、障碍和设备需求后，是否还有可互动空间；
- 当前结论的置信度、证据缺口和下一步需要哪张图或哪项实测。

不要用流畅叙述掩盖证据缺口。宁可保留“未知”，也不要补写不存在的页码、面积、尺寸、方位或空间关系。
